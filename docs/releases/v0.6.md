# SentinelGraph v0.6 — API, PostgreSQL, and Investigator Workflow

## Development outcome

v0.6 turns the offline v0.5 calibrated engine into a testable application. It
adds strict online features, single and batch scoring, auditable PostgreSQL
persistence, an investigator queue, feedback capture, and a browser dashboard.

## Delivered

- FastAPI factory with lifespan-loaded model and request-scoped database units.
- Single and bounded batch scoring with required idempotency keys.
- Exact 60-feature parity: ten event-derived plus 50 strictly-prior features.
- Startup rejection for missing, malformed, or checksum-mismatched artifacts.
- Calibrated probability, risk points, policy, components, and local reasons.
- PostgreSQL schema and Alembic migration for six durable tables.
- Atomic prediction/case/event creation and salted account pseudonyms.
- Investigator queue, case detail, assignment, close/disposition, and feedback.
- Optimistic locking for concurrent human decisions.
- API-key authentication, payload limits, liveness, readiness, and request IDs.
- Responsive dashboard that reads and writes only through protected endpoints.
- Unit, contract, HTTP integration, failure, and artifact tests.
- A local warm-model latency benchmark and service-quality report.
- Vectorized exact local occlusion, replacing 60 sequential serving calls with
  one batched perturbation call.

## Safety semantics

- `decline` remains a simulation-only recommendation.
- Online history must be supplied by a versioned point-in-time provider.
- Account identifiers are grouping/audit inputs, never model inputs.
- Raw identifiers are not persisted.
- Production requires PostgreSQL, non-default secrets, and model SHA-256.
- Joblib is loaded only from a pre-provisioned trusted local artifact.

## Deferred to v0.7

Docker, MLflow, CI/CD, distributed load testing, global rate limiting,
production metrics, drift detection, and automated rollback remain out of this
release so the API and data contracts can be reviewed independently.
